## 问题

什么是 agent 的幻觉？它和 LLM 的幻觉有什么区别？两者都怎么治理？

## 核心答案

**LLM 幻觉**：模型给出看起来合理、甚至很自信的内容，但和事实、和用户的问题对不上。治理是老几样：明确要求「只基于给定事实回答、不许编」、上 RAG 提供依据、降 temperature、输出后做引用核验。

**Agent 幻觉**：错误不在「说的话」，而在「做的事」。三种典型表现：

| 类型 | 表现 | 治理 |
| --- | --- | --- |
| 工具幻觉 | 调了不存在的工具、参数编造、该调不调 | 工具报错当结果回填让模型改；Schema + 程序校验拦非法参数；工具清单别让模型猜 |
| 压缩幻觉 | 摘要里丢了或改了关键事实（路径、金额、结论） | 摘要强制保留文件路径、改动记录、原始会话锚点，可回查原文 |
| 记忆幻觉 | 把旧记忆当成现行规则，按过期信息行动 | 记忆带写入时间戳；定位成「有帮助的回忆」而不是必须服从的规则；冲突时以当前事实为准 |

**一句话区别**：LLM 幻觉的错误停在文本里，Agent 幻觉的错误会落到**副作用**上——发错邮件、改错文件、下错单。

## 深度解析

- **根因是同一个**：模型在用概率补空缺。区别在于 Agent 有了「行动能力」和「状态」，补出来的空缺会被执行。
- **所以验证要升级**：LLM 时代验证「答案对不对」，Agent 时代要验证「状态对不对」——查数据库、查文件、查下游回执，而不是读一遍模型的自我描述。
- **两条通用兜底**：① 任何需要落库/对外发送的内容，前面必须有一层确定性校验（规则、Schema、二次核对）；② 关键动作前留人工确认点，把「纠错窗口」放在副作用之前。
