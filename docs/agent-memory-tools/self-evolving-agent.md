## 问题

「会自进化的 Agent」具体怎么实现？记忆和 Skill 各自怎么形成、优化、更新？

## 核心答案

**两条线**：memory 记住「人和项目」，skill 记住「怎么做」。

**一、记忆分层**

- 第一层 `soul.md`：系统提示词，定义 Agent 的对话风格，用户可调；
- 第二层 `user.md`：用户个人偏好；`memory.md`：项目经验（比如用户名下有哪些云资源、各自用途）。

**二、记忆的三件事**

- **检索**：新会话开始时，这两份核心文件作为**固定快照注入系统提示词**——Agent 一开始就能看到，不用每次按问题检索；会话中新产生的记忆会写盘，但不改写当前会话的这块提示词，下次会话才生效；
- **更新**：由模型判断哪些值得长期保存，再调 memory 工具：`add` 新增、`patch` 局部改、`remove` 删除，修改立即落盘；
- **遗忘**：过期、冲突的记忆要能删改，否则越用越错。

**三、Skill 的三步**

- **形成**：完成复杂任务、解决报错、或被用户纠正之后，让模型提炼「可复用的步骤 + 注意事项 + 验证方法」，存成 `SKILL.md`；
- **优化**：下次执行类似任务时加载已有 Skill，发现步骤遗漏、命令失效或用户有新要求，就结合执行结果反思出改进；
- **更新**：把改进写回原 Skill，优先局部修改；开了审批的场景，变更要经用户确认才生效。

## 深度解析

- **自进化的三个风险**：把一次偶然成功固化成规则（过拟合）、错误经验被写回（污染记忆）、Skill 越堆越多反而选不准。
- **对策**：写回前先验证（这次成功是不是可复现）、版本与来源可追溯、定期清理合并、关键变更走审批。
- **和 RAG 的区别**：RAG 是「查资料」，自进化是「改自己」——写入的是行为规则和操作手册，影响下一次的所有任务，所以写入权限要更严。
